# 技术决策记录

## ADR-001：使用 TypeScript 贯通前后端

**背景**：用户已有 React 基础，只有一周开发窗口，目标是前端与 AI 应用全栈岗位。

**决定**：基于 Vercel Chatbot 的 Next.js 工程，在 Node.js 服务端实现领域接口与 Agent 工具。共享 TypeScript 类型，运行时使用参数校验。

**影响**：减少跨语言协议维护与新服务运维，让时间集中于可演示的业务和验证。后续明确需要 Python 生态时，可以把模型或数据处理服务独立出来。

## ADR-002：保留上游身份与 UI 基础，新增独立调研领域

**决定**：保留上游许可证及来源记录。调研入口与接口独立放在 `/research`、`/api/research`，领域代码集中于 `lib/research`，不把模板已有功能列为个人新增贡献。

**影响**：评审者可以通过文件与提交识别新增能力。登录和基础 UI 可以复用，但资源授权仍需在每个新增接口中执行。

## ADR-003：本地使用 PGlite，兼容外部 PostgreSQL

**背景**：本机没有 Docker 与 psql；要求项目能先在本地跑通，同时实现 PostgreSQL 与向量查询。

**决定**：本地提供 PGlite + pgvector 路径，外部数据库通过 `POSTGRES_URL` 配置。本地引擎由启动器唯一持有，Next.js 工作进程通过本地 PostgreSQL 协议入口访问。

**影响**：无需另外安装数据库进程即可学习与演示。PGlite 的本地数据目录不能被多个应用进程随意共享，生产多实例部署应使用独立 PostgreSQL。数据库必须统一迁移，不能让每个请求重复建表。

## ADR-004：区分真实模型、演示执行与测试夹具

**决定**：真实模型通过服务端环境变量配置。缺少密钥时，允许明确标注的演示模式。GitHub 测试夹具仅由测试环境开启。

**影响**：开发者可以先完成产品与异常链路，测试具备可重复性；交付报告必须单独说明真实供应商联调是否执行。演示模式不伪装成 AI 推理效果。

## ADR-005：先做单 Agent 与三个有类型的工具

**决定**：围绕文档检索、仓库信息与 Issue 搜索形成一个完整任务循环。限制最大步数、参数范围、超时和重试。

**影响**：工具选择和报告来源可以清楚解释，错误也能定位到具体步骤。多 Agent、MCP Server 和画布编排留待确有需求时扩展。

## ADR-006：运行记录是产品数据，执行事件是前端协议

**决定**：持久保存报告、来源和工具事实；用结构化 SSE 传输增量状态。

**影响**：界面无需从模型文字猜测执行过程，也能在刷新后展示历史。后台长任务的跨进程检查点恢复不包含在本版默认承诺中。

## ADR-007：用独占启动器解决本地数据库的跨进程生命周期

**背景**：早期的进程内全局单例不能覆盖 Next.js 的多个工作进程。集成回归暴露了同一本地目录被不同引擎打开的生命周期问题。

**决定**：`scripts/serve.ts` 管理每个数据目录的 owner lock、迁移、本地引擎和 PostgreSQL socket。使用官方 `@electric-sql/pglite-socket`，只监听回环地址和随机端口，并把内部连接地址传给 Next.js；退出时按顺序释放资源。

**影响**：应用各工作进程通过 `postgres.js` 访问同一个数据库持有者，避免各自打开 PGlite。开发者必须通过项目启动脚本运行本地模式。外部 PostgreSQL 不经过本地 socket。这个设计解决本地进程边界，不提供多机器数据库能力。
