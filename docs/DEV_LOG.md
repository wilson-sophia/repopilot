## 2026-10-22：处理浏览器与 API 的集成差异

- Next.js `cacheComponents` 配置与路由上的部分运行时 / 动态配置导出不兼容，阻止接口编译；调整路由导出后重新验证。
- 中间一轮的 14 个 API 场景和 20 个固定工程 / 检索案例通过，但浏览器操作遭遇来源校验失败，因此没有把这一轮记为完整通过。
- 根因是框架可能把内部 `request.url` 归一化为 `localhost`，与浏览器访问的 `127.0.0.1` 不同；来源校验改用请求 `Host` 对应来源，并允许通过 `APP_ORIGIN` 显式声明反向代理的外部来源。
- 修复后启动整套干净回归；最终结果尚需等待本轮验证，不沿用中间通过数量作最终结论。

## 2026-10-22：修正本地数据库的跨进程持有

- 后续回归暴露了更深的生命周期问题：进程内全局单例不能阻止 Next.js 的不同工作进程各自打开同一 PGlite 数据目录。
- 增加 `scripts/serve.ts` 作为 `dev` / `start` 启动入口。按目录获取 owner lock，迁移后关闭初始化引擎，再由父进程唯一持有 PGlite 与 pgvector。
- 使用官方 `@electric-sql/pglite-socket` 在 `127.0.0.1` 随机端口提供 PostgreSQL 协议；Next.js 工作进程通过传入的内部 `POSTGRES_URL` 访问，分别使用本地 / 外部连接池上限 1 / 5。
- Ctrl+C / SIGTERM 触发子应用和数据库清理；独立 `setup:local` 拒绝打开正在使用的数据目录。
- 新默认目录采用 `.data/local-postgres`，旧 `.data/postgres` 留作失败诊断，没有把旧目录静默覆盖。
- 修复后重新启动干净回归。此处记录修复内容，最终通过状态仍等待本轮实测。

## 2026-10-22：补查生产包 HTTP 会话并修复跳转循环

- 构建完成后继续检查 `pnpm start` 的实际 HTTP 访问，发现模板原先按开发 / 生产环境选择 Secure cookie 的读取约定，可能与 Auth.js 根据 URL 协议设置的 cookie 不一致，导致访客入口反复跳转。
- 新增 `lib/auth-cookies.ts`，优先读取 `AUTH_URL`，兼容 `NEXTAUTH_URL`，未配置时使用请求 URL；根据是否为 HTTPS 选择 Secure cookie 读取规则。
- proxy 与 guest 会话入口共用该 helper，避免两个入口判断分叉。
- README 增加 `AUTH_URL`：本地 HTTP 使用实际 HTTP 地址；HTTPS 反向代理同时明确外部 `AUTH_URL` 与 `APP_ORIGIN`。
- 正在补充 helper 单元测试与生产包 HTTP 冒烟，并重新构建。此处只记录发现与修复内容，不宣称修复后的最终测试数量或生产运行已经通过；结果在实际执行后追加。

## 2026-10-22：生产冒烟捕获初始化落盘问题

- 新增的生产包 HTTP 冒烟首轮实际返回 500，没有因为之前构建与开发流程通过就忽略此失败。
- 只读检查与实际失败共同定位到：没有外部 `POSTGRES_URL` 且 `NODE_ENV=production` 时，连接层为隔离构建过程选择内存数据库；启动器迁移也误入该分支，迁移实例关闭后，随后打开的磁盘数据库缺少表。
- 修复为本地初始化时明确设置内部 `RESEARCH_LOCAL_DB=1`，连接层仅在生产构建环境且没有该标志时使用内存。运行期启动器会迁移磁盘数据，构建工作进程仍不接触用户数据目录。
