# 跨轮调研记录与证据复用

同一项目的后续问题默认继承最近完成的调研记录，不再要求每轮重新读取同一仓库和资料。它与同一轮任务的检查点恢复是独立能力。

## 继承内容

新运行记录保存父运行ID、资料范围签名和最近3轮问答，每轮历史报告最多2500字符，作为背景信息而非新的事实来源。已有原文证据按原来源编号传入模型，每段最多传入700字符；需要更多细节时继续调用读取工具。

最多继承40个来源和20条已完成的查询工具结果；相同工具和参数直接返回已保存结果，界面标记“复用结果”。源码继续使用已保存的提交快照，允许补读新文件和新行号。新问题仍创建独立运行记录，自己的步骤预算从0开始；没有复制上一轮的模型执行消息和步数。

## 失效与主动刷新

- 仅查询当前所有者、当前项目、相同运行模式与资料范围的已完成记录。
- 资料范围包含仓库、项目描述、文档ID与状态、Embedding空间。资料变更后不继承旧范围的证据。
- 只复用24小时内的记录与来源；超过来源数量限制、来源过期时不继承历史上下文。
- 页面提供“重新查证（不复用历史证据）”，API对应 `refresh: true`；本轮不继承历史，重新读取远程默认分支与资料。默认固定提交不代表远程最新版本，关注最新改动时应主动重新查证。
- 仓库元数据和Issue工具记录不进入可复用工具缓存，避免把动态查询当作源码快照缓存。
- 历史报告是背景，原文证据才支持结论；外部内容不能成为工具权限或系统指令。

## 验证

真实模型与浏览器连续3轮通过：第一轮2次新工具查询；第二轮0次新查询、2条复用记录；第三轮勾选重新查证后4次新查询，且无父运行记忆。刷新后记录仍存在。

模拟真实模型用例断言后续请求含前一轮回答和原文证据，第二轮可直接生成引用回答且工具ID保持不变。API测试验证继承、主动刷新、删除资料后的失效；已有权限测试继续验证跨用户和跨项目访问限制。共45项单元／契约与27项API／浏览器测试通过。
