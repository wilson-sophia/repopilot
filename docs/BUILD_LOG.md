## 已记录的实现检查点

1. **领域契约先行**：建立共享的项目、文档、工具、来源、运行与 SSE 事件类型，避免前后端各自推断数据格式。
2. **本地数据入口**：初始化脚本统一执行上游与调研领域迁移。开发模块热更新时复用进程内数据库实例，减少本地引擎重复打开。
3. **识别命令冲突**：`pnpm setup` 是包管理器命令；项目脚本改为明确的 `pnpm run setup:local`。
4. **分开执行模式**：演示模式、真实供应商模式、GitHub 测试夹具分别配置，避免将固定数据误报为外部服务联调成功。
5. **保留学习材料**：原始 README、示例需求、接口说明、技术决策和面试复盘与代码共同保留。

## 实际问题与修复顺序

1. **初始化脚本名称与执行方式**：项目脚本使用 `pnpm run setup:local`；脚本运行器使用 `node --import tsx`，避免 `tsx` CLI 在受限环境中的 IPC 创建失败。
2. **向量扩展导入位置**：按当前依赖版本使用 `@electric-sql/pglite-pgvector`，并在 Next.js 服务端外置本地数据库包。
3. **模型 SDK 的重复版本**：实际类型检查暴露 Provider 类型不兼容；统一 `ai@7.0.148` / `@ai-sdk/provider@4.0.31` 系列及关联适配器后复查。
4. **路由与框架配置**：`cacheComponents` 与部分路由配置导出冲突，需先解决编译问题，再开展 API 回归。
5. **浏览器来源与内部 URL**：API 测试曾通过，但真实浏览器请求被来源检查拒绝。检查浏览器可见的 Host，并提供 `APP_ORIGIN` 后重新跑整套流程。
6. **进程内单例不是跨进程锁**：Next.js 的不同工作进程仍可能各自打开同一 PGlite 目录。最终采用唯一持有本地引擎的 `scripts/serve.ts`，通过官方 PostgreSQL socket 给工作进程提供连接；加入目录锁与退出清理。默认目录改为 `.data/local-postgres`，旧目录保留作失败诊断。
7. **生产构建通过不等于生产运行通过**：继续以生产包通过 HTTP 访问时，发现模板的会话 cookie 读取规则可能引发访客跳转循环。新增 `lib/auth-cookies.ts`，按 `AUTH_URL` / `NEXTAUTH_URL` / 请求 URL 协议选择 Secure cookie，供 proxy 与 guest 入口复用；对应单测与生产包冒烟正在补充，修复后的结果待独立验证。
8. **构建期隔离不能跳过运行期迁移**：新增生产包冒烟的首轮实际返回 500，暴露无外部 PostgreSQL 时的初始化问题：`NODE_ENV=production` 让迁移进入内存实例，关闭后磁盘库仍缺少表。修复为初始化本地磁盘时显式设置内部标志 `RESEARCH_LOCAL_DB=1`，仅构建工作进程在无此标志时使用内存隔离；第二轮验证功能后继续修复退出清理，最终结果见下节。
9. **退出顺序需要等待延后回调**：官方 socket 停止后仍有延后关闭回调，启动器先等待一个 `setImmediate` 周期，再关闭数据库；本地主动触发的 SIGTERM 作为正常退出处理。修复后重启持久性重跑通过，日志未出现类型错误、未处理拒绝或 WASM 中断。
10. **构建追踪应排除运行数据**：NFT 清单曾包含本地数据和测试输出，加入 Turbopack 忽略与 `outputFileTracingExcludes` 后重建通过。研究接口清单实测 335 个文件，数据 / 测试结果 / 环境文件引用均为 0；全量扫描结果仍等待生产冒烟确认。
