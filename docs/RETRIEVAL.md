# 文档增强与混合检索

本实现借鉴 OpenDatabase 的元数据增强与双路召回思路，面向短需求文档，不引入新的上传流程或独立搜索服务。

## 入库

1. 沿用文档解析和重叠分块。
2. 真实模式中，每个片段由聊天模型提取最多 8 个关键词、生成最多 3 个可由原文直接回答的假设性问题。最多并发 3 个片段请求，每次请求最长 15 秒。
3. 保留 `content` 原文，另外保存 `retrieval_metadata` 和 `search_text`。检索文本为原文、关键词和问题的组合，其向量用于语义召回；最终给报告的引用片段仍为原文。
4. 生成元数据失败或响应格式无效时，记录 `enrichment: fallback`，使用本地关键词及原文继续索引，不伪造已生成问题。演示模式记录 `local`，不调用模型、不生成问题。
5. 向量生成完成后，文档、分块、元数据在同一事务中写入。

这里生成的是索引阶段的假设性问题，不是查询阶段生成假设性答案的 HyDE。生成文本只帮助发现原文，不能作为事实来源。

## 查询

- 向量路：按项目、向量空间过滤，以余弦相似度取前 10 个候选并做阈值过滤。
- 关键词路：对增强检索文本、文件名做参数化字面子串匹配，以命中关键词数量排序，取前 10 个。兼容中文和技术标识符，输入中的 `%`、`_` 不作为通配符。本方案是小规模项目内关键词检索，不声称为 BM25。
- 融合：每条路线内部去重，按 `sum(1 / (60 + rank))` 做 RRF，避免直接混加不同量纲的分数。相同片段内容再次去重，保留最多 15 个融合候选，默认返回前 5 个原文来源。
- RRF 是排序信号，不是概率或语义置信度。应以实际问题集比较单路和混合检索的 Recall@K、命中排序及无证据问题误召回，不能预先宣称效果提升。
- 两路查询都经过所有权检查，且均限定项目与向量空间，模型不能扩大查询范围。

查询改写和模型重排序不是默认步骤。可通过 `RESEARCH_QUERY_REFINEMENT=1` 开启：改写失败使用原问题，重排失败使用融合排名；有效空结果保持为空，取消信号继续向上传播。当前工具没有多轮检索会话历史，因此不宣称支持基于历史对话的代词消解。

## 兼容与运行

启动初始化会幂等添加新列，旧分块无需删除，关键词路对空 `search_text` 使用原文。旧文档不会静默调用模型回填：想获得假设性问题与增强向量，请删除后重新导入。切换 Embedding 模型也需要重新导入。

```powershell
pnpm test:unit
pnpm exec playwright test -c playwright.research.config.ts
node --import tsx scripts/check-hybrid-live.ts
```

最后一条会使用 `.env.local` 中配置的真实模型和 Embedding，产生少量 API 用量，在临时数据库验证元数据生成、向量化、检索、工具调用、引用报告及持久化，不修改用户项目数据。
